## Security

We take the security of our software seriously. If you believe you have found a security vulnerability in any of our projects, please report it as described below.

## Reporting Security Issues

See [Privately reporting a security vulnerability](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability) for information on how to submit a vulnerability report to the project maintainers via GitHub.

> [!CAUTION]
> Please do not report security vulnerabilities through **public** GitHub issues or other public forums.

If you do not receive a response within 48 hours, please contact a maintainer directly through any method available on their public profile.

Please include as much of the requested information listed below as possible to help us better understand the nature and scope of the potential vulnerability:
* Type of issue
* Full paths of source file(s) related to the manifestation of the issue
* The location of the affected source code (tag/branch/commit or direct URL)
* Any special configuration required to reproduce the issue
* Step-by-step instructions to reproduce the issue
* Proof-of-concept or exploit code (if possible)
* Impact of the issue, including how an attacker might exploit the issue

This information will help us triage your report more quickly.

## Preferred Languages

We prefer all communications to be in English.
